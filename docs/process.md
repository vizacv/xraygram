# Регламент Xraygram (ITIL-lite)

Цель: все темы работают по одним правилам. Каждая задача, сборка и баг имеют ID, владельца и статус,
поэтому никто никого не ждёт вслепую и ничего не теряется.

## Роли (RACI)

| Роль | Кто | Отвечает за |
|---|---|---|
| **Владелец** | Никита | приоритеты, решения «делаем/не делаем», приёмка релиза, живые тесты с людьми и телефонами |
| **Оркестратор** (service desk, change и release manager) | главная тема `~/xraygram` | общение с владельцем, маршрутизация задач, git (коммит/пуш), этот регламент, реестры `docs/` |
| **Продукт** (product owner) | тема «Xraygram продукт», `product/` | бэклог фич, спецификации, единое поведение на всех платформах, приоритеты (предлагает владельцу), тексты UI |
| **Платформа** (macOS, Android, iOS) | системные темы | реализация по спецификации, сборки-кандидаты, регистрация сборок, база знаний своей папки |
| **Тестирование** (QA) | тема «Xraygram тестирование», `testing/` | автопроверка **каждой** зарегистрированной сборки, регресс, реестр багов, вердикт «можно владельцу / нельзя» |

R — делает, A — утверждает:

| Процесс | Владелец | Оркестратор | Продукт | Платформа | QA |
|---|---|---|---|---|---|
| Новая фича (идея → спецификация) | A | R (заводит запрос) | R (спека) | C | C |
| Изменение в коде | — | A (маршрут) | C | R | — |
| Сборка-кандидат | — | I | I | R | I |
| Проверка сборки | — | I | I | C | R/A |
| Выдача сборки владельцу и коммит | A | R | I | I | C |
| Баг | I | I | C (приоритет) | R (фикс) | R (завод, проверка фикса) |

## Поток работы

```
Запрос (владелец) → FEAT/BUG в реестре → спека (продукт) → задача платформам (оркестратор)
→ код + сборка (платформа) → регистрация сборки + сообщение QA (платформа)
→ автопроверка (QA) → вердикт → владельцу и в git (оркестратор) → приёмка (владелец)
```

1. **Запрос.** Владелец пишет оркестратору. Оркестратор заводит `FEAT-NN` или `BUG-NN` в `docs/backlog.md` и передаёт
   продукту (фича) или QA и платформе (баг).
2. **Спецификация.** Продукт пишет `product/features/FEAT-NN.md`: зачем, поведение по шагам, тексты, одинаково для всех
   платформ, критерии приёмки (их же проверяет QA). Если нужна развилка, продукт формулирует вопрос с рекомендацией,
   оркестратор задаёт его владельцу.
3. **Реализация.** Платформа делает по спеке. Отклонения (платформа так не умеет) — согласовать с продуктом, не молча.
4. **Сборка.** Тяжёлые шаги — только через `tools/heavy-build.sh <тема> ...`. Готовая сборка получает ID и
   **регистрируется** в `docs/builds.md` (см. ниже). Файл сборки не перезаписывать, пока он «у владельца» —
   новую класть рядом с новым именем.
5. **Автопроверка.** Сразу после регистрации платформа **сама пишет QA** (SendMessage `xraygram-tester`): ID сборки,
   путь, что изменилось, какие FEAT/BUG закрывает. QA прогоняет автоматический смоук своей платформы и критерии
   приёмки затронутых FEAT, ставит вердикт в `docs/builds.md` и пишет оркестратору.
6. **Выдача.** Оркестратор отдаёт владельцу только сборки с вердиктом QA «✅» (или «⚠️» с явным списком ограничений),
   коммитит патчи/скрипты/доки этой сборки и пушит.
7. **Приёмка.** Владелец проверяет руками то, что QA не может (живые звонки, телефоны, вход). Результат — в реестр.

## Реестры (единый источник правды)

| Файл | Ведёт | Что |
|---|---|---|
| `docs/backlog.md` | продукт (оркестратор заводит) | фичи `FEAT-NN`: приоритет, статус на каждой платформе |
| `docs/bugs.md` | QA | баги `BUG-NN` (старые `MAC-NN` остаются в отчётах): важность, платформы, статус |
| `docs/builds.md` | платформы регистрируют, QA ставит вердикт | все сборки: ID, файл, что внутри, вердикт QA, у владельца ли |
| `docs/decisions.md` | оркестратор | решения владельца и почему |
| `docs/orchestration.md` | оркестратор | темы, их сессии, что ждёт владельца |

Статусы: `—` не начато · `🔨` в работе · `🧪` собрано, ждёт QA · `✅` проверено · `⚠️` с оговорками · `❌` сломано ·
`👤` ждёт владельца · `🚫` не делаем.

## ID сборок

`<платформа>-<ГГГГММДД>-<N>`, например `android-20261118-2`. Файл сборки кладётся с этим ID в имени
(`Xraygram-android-20261118-2.apk`), чтобы старые не перезаписывались. Для macOS — копия бандла/DMG с ID.

## Отчёт платформы (формат)

Каждый отчёт платформы оркестратору — по одному шаблону:

```
Сборка: <ID> (<путь>)          | или «без сборки»
Сделано: FEAT-.., BUG-..       | одной строкой
Проверено мной: ...            | коротко
Не проверено: ...
Нужно от владельца: ...        | или «ничего»
QA уведомлён: да/нет
```

## Правила, которые не меняются

- Пишешь только в свою папку (+ `upstream/<свой клон>`); общее — через оркестратора.
- Коммит и пуш — только оркестратор.
- Секреты не выводить и не коммитить; всё внутри `~/xraygram`.
- Чужой запущенный процесс (приложение владельца) не закрывать и не убивать.
- Язык — русский.
