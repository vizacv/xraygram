# Решения

- **2026-11-18** — xray встраиваем как локальный SOCKS5 (in-process или дочерний процесс),
  сетевой код Telegram не переписываем. Причина: MTProto/mtg не работает ~год, нужен VLESS+Reality.
- **2026-11-18** — сборки только в GitHub Actions: на Mac нет Go/Java/Gradle/Xcode, а нативная часть Telegram тяжёлая.
- **2026-11-18** — первый тестовый вариант: **macOS, Telegram Desktop (tdesktop)**, arm64 (Apple Silicon).
  Почему не нативный Swift-клиент (`overtake/TelegramSwift`): у tdesktop есть рабочий upstream CI для macOS
  и тот же форк потом даёт Windows/Linux; сборка TelegramSwift под Xcode 26 сейчас сломана, CI нет.
- **2026-11-18** — Android на паузе; материалы в `android/`.
- **2026-11-18** — репозиторий https://github.com/vizacv/xraygram **публичный**: в публичных репо GitHub Actions
  бесплатны без лимита, а в приватном macOS-минуты считаются ×10 (≈200 мин/мес). GPL и так требует открытый код.
  Секреты — только GitHub Secrets.
- **2026-11-18** — тестовые итерации делаем **локально** на MacBook Air M5: инкрементальная пересборка — минуты
  против ~1 ч в CI (раннер macOS — 3 ядра). В публичный репо уходит только проверенное; CI — эталонная сборка для раздачи.
  api_id/api_hash локально — `~/xraygram/.secrets/api.env` (0600, в .gitignore).
- **2026-11-18** — CI на GitHub **не гоняем** на тестовых итерациях (run 44271794787 отменён). Workflow остаётся
  только с ручным запуском (`workflow_dispatch`), сам не стартует; запускаем осознанно, когда нужна эталонная сборка.
  Первая локальная сборка: 18 мин, патч скомпилировался без ошибок.
- **2026-11-18** — всё рабочее держим **внутри `~/xraygram`**, домашнюю папку не засоряем: ключи в `.secrets/`,
  сборка, Rust и кэши Go — в `upstream/xraygram-local/`. Снаружи только неизбежное: Homebrew-пакеты, Xcode, конфиг `gh`.
- **2026-11-18** — macOS-версия проверена владельцем: вход и XRAY-подключение работают (коммит `6f7fdf3`).
- **2026-11-18** — iOS: Telegram-iOS, xray внутри процесса (libXray xcframework), подпись бесплатным Apple ID (7 дней, iPhone по кабелю).
  Android: собираем локально. iOS и Android работают параллельно, тяжёлые сборки идут по очереди (`tools/heavy-build.sh`).
  Нативный Swift-клиент для macOS (TelegramSwift) — после iOS, на том же ядре TelegramCore/MtProtoKit.
- **2026-11-18** — отдельная тема тестирования (`testing/`): чек-листы, проверка утечек, звонков, жизненного цикла core.
- **2026-11-18** — звонки через xray: делаем **один патч tgcalls** (SOCKS5 на port allocator в v2, только TCP-relay),
  сначала на macOS (быстрые итерации), потом переносим на Android и iOS. Групповые звонки — сначала оценка;
  если дорого — предупреждение в UI, что они идут без xray.
- **2026-11-18** — первый запуск (MAC-05): **экран «Добавьте XRAY»**. Пока нет XRAY-записей, клиент в сеть не ходит;
  есть явный выход «напрямую» с подтверждением. Поведение одинаковое на всех платформах.
- **2026-11-18** — иконка: обезьянка с самолётиком (макет владельца), ассеты в `branding/`. Встраивать не сразу,
  а вместе со следующими изменениями каждой платформы.
