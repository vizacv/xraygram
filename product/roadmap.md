# Дорожная карта (предложение продукта владельцу)

2026-11-18. Принцип: сначала то, без чего нельзя дать Xraygram другу (P1 + выравнивание утечек), потом то, что
спасает при блокировке серверов, потом шлифовка и раздача шире.

## Порядок

1. **Закрыть утечки, найденные при сверке платформ** (PAR-08, PAR-09, PAR-05, PAR-04; 1 короткий круг на платформу).
   Android сейчас может пустить звонок напрямую (версия Pump), групповые звонки на Android/iOS уходят напрямую без
   предупреждения, а выключатель прокси везде молча уводит «напрямую». Это прямо против правила «не светиться».
2. **Живой звонок 1:1 на macOS** (владелец + второй человек, ~15 мин по `macos/README.md`). Это единственная проверка,
   от которой зависит FEAT-04 на всех трёх платформах: если Telegram не отдаёт TCP-ретрансляторы, подход меняется.
3. **Сборки-кандидаты Android и iOS с FEAT-01…04 → QA по критериям F0N-NN.** Android: зарегистрировать APK с экраном
   XRAY и звонками. iOS: подпись бесплатным Apple ID (нужен владелец, `ios/README.md`).
4. **FEAT-09 — уведомления на Android по умолчанию.** Без этого тест у друзей покажет «сообщения не приходят».
5. **Выравнивание текстов и ошибок** (PAR-01/02/03): одинаковые русские и английские тексты, понятные ошибки ссылки.
   Затем **комплект для друга** (FEAT-17): одна страница «как поставить, куда вставить ссылку, что не работает».
   → **Тест на телефонах друзей.**
6. **Устойчивость к блокировкам:** автовыбор живого сервера (FEAT-14), затем импорт подписки (FEAT-13).
   Это то, что реально будет нужно через месяц, когда первый сервер заблокируют.
7. **Перед раздачей шире друзей:** своя иконка и имя (FEAT-07, правила Telegram для форков), WebView через xray или
   предупреждение (FEAT-10), эталонные сборки CI (FEAT-11).

## Новые идеи фич

Оценка: польза для пользователя в РФ / сложность (на все три платформы).

### 1. Автовыбор живого сервера (FEAT-14) — польза **высокая**, сложность **низкая–средняя**

Когда активный сервер перестал отвечать, клиент сам переходит на другую XRAY-запись, без похода «напрямую».
В Telegram уже есть ротация прокси (Android, iOS, tdesktop): клиент перебирает список, если текущий не подключается.
Нужно: ротация включена по умолчанию, перебирает **только XRAY-записи**, таймаут ~10–15 с, в строке записи видно, что
переключились. Работа в основном в настройках и фильтре списка, ядро не трогаем. Без этой фичи несколько записей
(FEAT-02) полезны только тем, кто сам заметит «Подключение…» и переключит.

### 2. Импорт подписки (FEAT-13) — польза **высокая**, сложность **средняя**

Владелец даёт другу не `vless://`, а одну ссылку `https://…/sub/…` (её выдают панели 3x-ui, Marzban, Remnawave).
По ней приходит список серверов (base64-список ссылок). Xraygram создаёт XRAY-записи из списка и раз в сутки (и по
кнопке) обновляет их. Заблокировали IP — владелец меняет сервер в панели, у друзей список обновляется сам.
Вопросы, которые решим в спеке: первая загрузка подписки идёт напрямую (это HTTPS к панели владельца, не к
Telegram — для ТСПУ безопасно), последующие — через активную XRAY-запись; удалённые из подписки записи уходят в
«сохранённые»; заголовки `profile-title`/`subscription-userinfo` показываем как имя и «осталось N ГБ / до даты».
В поле ссылки (FEAT-01) сейчас `https://` даёт понятную ошибку — потом станет вторым способом ввода.

### 3. Предупреждение о «заметной» ссылке (FEAT-16) — польза **средняя**, сложность **низкая**

При проверке ссылки (FEAT-01) показываем жёлтое предупреждение, не ошибку: Reality без `flow=xtls-rprx-vision`,
без `fp` (отпечаток TLS), `security=none` поверх TCP/WS, TLS к голому IP без SNI, устаревший `vmess` без TLS.
Такие ссылки ТСПУ находит быстрее. Сделать легко: ядро уже разбирает ссылку, нужно 5–6 правил и тексты.
Полезнее для владельцев серверов, чем для друзей, поэтому P3.

QR (сканирование и показ) — внутри FEAT-15, после решения В1.

## Вопросы владельцу

Формат: вопрос → варианты → рекомендация продукта. Оркестратор задаёт.

**В1. Можно ли делиться XRAY-сервером из приложения (QR / «Поделиться»)?**
- а) Да, с предупреждением «Кто получит ссылку, сможет пользоваться вашим сервером», QR и копирование ссылки
  на всех платформах; сканирование QR на телефонах — следующим шагом (FEAT-15).
- б) Нет нигде (как iOS сейчас): ссылку раздаёт только владелец, своими средствами.
- в) Только Android (как сейчас).
- **Рекомендация: а).** Владелец сам раздаёт доступ друзьям, а QR с экрана — самый простой способ передать длинную
  ссылку на телефон. Предупреждение защищает от случайной утечки ключа.

**В2. Что делает выключатель «Использовать прокси», когда есть XRAY-записи?**
- а) Подтверждение «Подключиться напрямую?» (как выход «без XRAY» на экране XRAY), потом — напрямую.
- б) Запрещено совсем: пока есть XRAY-записи, «без прокси» выбрать нельзя (жёсткий kill switch).
- в) Как в Telegram — молча напрямую (сейчас так на всех платформах).
- **Рекомендация: а).** Не даёт уйти напрямую случайно, но не запирает человека, которому правда нужно напрямую
  (например, сервер умер, а Telegram в этой сети не заблокирован).

**В3. Язык интерфейса Xraygram-экранов.**
- а) Русский и английский по языку системы (Android уже так).
- б) Только русский (macOS и iOS сейчас так).
- **Рекомендация: а).** Стоит немного (одна таблица строк), а у части друзей телефон на английском — тогда на экране
  была бы смесь английского Telegram и русских XRAY-экранов.

**В4. Уведомления на Android (FEAT-09) — в P1 перед тестом у друзей?**
- а) Да: фоновое соединение включено по умолчанию + одно объяснение и запрос «работа в фоне».
- б) Нет: оставить ручную настройку и описать в инструкции.
- **Рекомендация: а).** Без уведомлений мессенджер у друга выглядит сломанным; цена — постоянное уведомление
  «Xraygram на связи» и немного батареи.

**В5. Нужен ли Windows-клиент (FEAT-18)?** Патч tdesktop почти кроссплатформенный, но это ещё одна сборка и тест.
- а) Да, после теста на телефонах друзей.
- б) Нет / потом.
- **Рекомендация:** ответить по факту, есть ли у друзей Windows; по умолчанию б).
