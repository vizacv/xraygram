# FEAT-04 — Звонки 1:1 через xray (+ предупреждение перед групповым звонком)

Приоритет: **P1**. Решение владельца 2026-11-18: один патч tgcalls (SOCKS5 в port allocator v2, только TCP-relay),
сначала macOS, потом Android и iOS. Связано: BUG-01 (звонки шли напрямую), BUG-02 / FEAT-05 (групповые).
Патчи: `macos/patches/tgcalls/`, `android/patches/tgcalls/`, `ios/patches/tgcalls/`.

## Зачем

Звонок напрямую — это и утечка (провайдер видит UDP к серверам Telegram), и чаще всего «не соединяется» при
блокировке. Пользователь не должен ничего включать: если активна XRAY-запись, звонок идёт через неё.
Групповые звонки пока через xray не идут (FEAT-05) — значит, человек должен узнать об этом **до** входа, а не потом.

## Поведение (одинаково на всех платформах)

### Звонок 1:1 (голос и видео), входящий и исходящий

1. Если активна XRAY-запись и прокси включён, звонок **всегда** идёт через локальный SOCKS5 этой записи. Галки
   «Использовать прокси для звонков» для XRAY нет (скрыта); для обычных SOCKS5-прокси — как в Telegram.
2. Транспорт: только relay-кандидаты на **TCP-ретрансляторах** Telegram, каждое соединение — через SOCKS5 xray.
   UDP, STUN, прямой P2P и прямой TCP выключены.
3. **Версии протокола звонка:** при активной XRAY-записи клиент предлагает и принимает **только** те версии, чья
   реализация идёт через патч (сейчас v2 `InstanceV2Impl` и `InstanceV2ReferenceImpl`: 7–13). Версии, реализация которых
   прокси не принимает или не пропатчена (`InstanceV2CompatImpl` 14, `InstanceV2PumpImpl` 18/19, и т. п.), при XRAY не
   предлагаются. Старые v1 (`InstanceImpl`, 2.7.7/5.0.0) — только если платформа проверила, что они идут через SOCKS5
   без UDP; иначе тоже исключить.
4. Если собеседник умеет только исключённые версии или Telegram не выдал TCP-ретрансляторы — звонок **не соединится,
   но и напрямую не пойдёт** («лучше не соединится, чем тихая утечка»). Пользователь видит штатное «не удалось
   соединиться». (Свой понятный текст — после живого теста, когда станет ясно, как часто это бывает.)
5. Если активна не-XRAY запись или прокси выключен — поведение upstream без изменений.

### Перед групповым звонком / видеочатом / конференцией / трансляцией

6. Если активна XRAY-запись и пользователь входит в групповой звонок, видеочат, конференцию или начинает трансляцию —
   **перед подключением** диалог «Без XRAY» (тексты ниже). «Продолжить» — вход как обычно (напрямую), «Отмена» — не
   входим. Показывается при каждом входе (в этой версии без «больше не спрашивать»).

## Платформенные отличия (допустимые)

- Набор зарегистрированных реализаций звонка разный: macOS (tdesktop) — v1 + V2 + Reference; Android — v1 + V2 +
  Reference + **Pump** (18/19); iOS — V2 + Reference + Compat (14) + Pump. Список разрешённых при XRAY версий каждая
  платформа выводит из своего набора по правилу п. 3.
- Входящие звонки в фоне: Android — только при фоновом соединении (FEAT-09); iOS с бесплатным Apple ID — только
  пока приложение открыто (нет VoIP push). Это ограничение, а не отличие поведения звонка.
- База tgcalls разная (macOS — из tdesktop 7.4.4, Android `545f5ae`, iOS `c1de0882`): патч один по смыслу, по
  тексту три.
