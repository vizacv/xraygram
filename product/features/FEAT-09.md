# FEAT-09 — Уведомления на Android: настоящие пуши FCM, фоновое соединение как запасной вариант

Приоритет: **P1** (В4 — владелец согласился, 2026-11-18). Платформы: **Android**.
macOS — n/a (приложение на рабочем столе само держит соединение). iOS — n/a: пуши APNs нужны платному аккаунту
Apple, с бесплатным Apple ID их нет. Это ограничение пишем в инструкции (FEAT-17).
Связано: BUG-15 (FCM ходит к Google мимо xray: осознанное исключение, см. ниже), FEAT-03 (блокировка до XRAY),
FEAT-04 (входящие звонки).

Редакция 2: первая версия (только фоновое соединение) заменена. На my.telegram.org для нашего api_id есть
«Push credentials → FCM service account». Значит, Telegram может слать пуши в **наш** проект Firebase, и
Xraygram получает их так же, как официальный клиент.

## Зачем

Без пушей друг на Android получает сообщения, только пока приложение открыто. Фоновое соединение спасает, но тратит
батарею, держит постоянное уведомление и не переживает агрессивные прошивки (Xiaomi, Samsung). Пуши FCM приходят
всегда, будят приложение и для входящих звонков, батарею не тратят. Фоновое соединение остаётся для телефонов без
Google Play (Huawei и т. п.).

## Как это устроено

```
Telegram ──(FCM service account нашего проекта)──► Google FCM ──► Google Play services на телефоне ──► Xraygram
Xraygram ──(account.registerDevice, token_type=2, через MTProto → xray)──► Telegram
```

- Токен FCM приложение получает у Google. Это Firebase Installations и регистрация FCM, **напрямую, не через
  xray**. Отдаёт его Telegram через MTProto, то есть через xray.
- Содержимое пуша Telegram шифрует ключом авторизации аккаунта. Google видит только факт пуша, размер и время.
- Разбуженное пушем приложение поднимает xray внутри своего процесса. Дальше всё идёт через него: загрузка
  сообщения, ответ на звонок.

## Что делает владелец (один раз; пошаговую инструкцию даёт оркестратор)

1. Firebase Console: создать проект, Google Analytics **выключить**.
2. Добавить Android-приложение с пакетом `io.github.xraygram`. Скачать `google-services.json` и положить в
   `~/xraygram/.secrets/google-services.json` (права 0600). В git он не попадает: репозиторий публичный, а в
   файле ключ API проекта.
3. Google Cloud проекта: включить «Firebase Cloud Messaging API (V1)», если не включён.
4. Настройки проекта → Service accounts → создать закрытый ключ (JSON). Загрузить его на my.telegram.org → наш
   api_id → Push credentials → **FCM service account**. Ключ не попадает ни в git, ни в приложение, ни в чаты. После
   загрузки локальную копию удалить или держать только в `.secrets/`.
5. Сказать оркестратору «готово». Дальше Android-тема собирает APK.

## Поведение

### Пуши FCM (основной путь)

1. В сборке используется `google-services.json` владельца из `.secrets/`. Если файла нет, сборка идёт как сейчас:
   FCM выключен, только фоновое соединение. Скрипт сборки предупреждает об этом.
2. **Пока действует блокировка FEAT-03** (нет XRAY и не выбрано «напрямую»), Firebase **не инициализируется**:
   ни Installations, ни токен, ни какой-либо запрос к Google. Первый запуск остаётся тихим.
3. После снятия блокировки (первое «Подключить» или явное «напрямую») включается автоинициализация FCM:
   - приложение получает токен;
   - отправляет его в Telegram через `account.registerDevice` (тип 2, FCM) по MTProto, то есть через xray;
   - при смене токена отправляет новый.
4. Пришёл пуш, приложение закрыто или выгружено: приложение просыпается и сразу поднимает xray для активной
   XRAY-записи. Уведомление показывается штатно, с текстом, если Telegram положил его в пуш. Иначе приложение
   догружает сообщение через xray.
5. Входящий звонок пушем будит приложение. Экран звонка показывается штатно, звонок идёт через xray (FEAT-04).
6. Из Firebase в приложении работают **только** Messaging и Installations. Analytics, Crashlytics, App Indexing,
   Remote Config, SafetyNet / Play Integrity, Phone Number Verification (`firebase-pnv`) выключены или не
   вызываются. Резервный поиск адресов Telegram через Firebase/DoH остаётся выключенным (FEAT-03, п. 4).
7. Если FCM работает, «Keep-Alive Service» и «Background Connection» остаются как в upstream (выключены):
   постоянного уведомления нет.

### Запасной путь: фоновое соединение

8. **Когда включается:** на телефоне нет Google Play services, или токен FCM не получен за 60 с после снятия
   блокировки, или FCM вернул ошибку регистрации. Тогда автоматически:
   - включаются «Keep-Alive Service» и «Background Connection»;
   - один раз показывается объяснение «Уведомления в фоне» с кнопкой «Разрешить». Она открывает системный запрос
     «Не оптимизировать расход батареи» (`ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`).
9. Если позже FCM заработал (поставили Google Play, сеть к Google появилась), ничего само не выключается. В
   настройках видно, что FCM работает, и фоновое соединение можно выключить руками.

### Общее

10. Android 13+: разрешение на уведомления запрашивается штатно сразу после снятия блокировки, в обоих путях.
11. В «Уведомления и звуки» есть строка состояния доставки (тексты ниже). Для запасного пути при ограничении
    батареи нажатие на строку открывает тот же системный запрос.

## BUG-15 — осознанное исключение

Решение оркестратора (2026-11-18), продукт согласен. BUG-15 → **🚫 by design при FCM**.

Допускаются соединения процесса Xraygram с Google **мимо xray**, но только такие:

- **Что:** Firebase Installations и регистрация или обновление токена FCM. Сама доставка пушей идёт через
  процесс Google Play services, не через наш.
- **Когда:** только после снятия блокировки FEAT-03.

Почему это не утечка по смыслу:

- Google в РФ не заблокирован. Любой Android-телефон говорит с теми же адресами постоянно, так что для ТСПУ это
  обычный фон.
- Это не соединение с Telegram. К Telegram и его IP-диапазонам по-прежнему ни байта мимо xray.
- Содержимое пушей зашифровано Telegram.

Что остаётся багом:

- соединение с Google **до** снятия блокировки;
- любые другие сервисы Google и Firebase из процесса приложения (Analytics, Crashlytics, App Indexing, Remote
  Config, pnv);
- любое соединение с Telegram мимо xray.

`testing/plan.md` (LEAK) учитывает это исключение: разрешённые хосты — `firebaseinstallations.googleapis.com`,
`fcmregistrations.googleapis.com`, `fcmtoken.googleapis.com`, `android.clients.google.com` (QA уточняет список по
факту).

## Платформенные отличия

Только Android. Huawei/HMS-пуши (у Telegram есть тип HCM) не делаем: такие телефоны идут запасным путём. На
прошивках с собственным «автозапуском» или «спящими приложениями» (MIUI, EMUI, One UI) шаги для друга пишем в
инструкцию (FEAT-17).
