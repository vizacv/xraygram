# Решения iOS (Telegram-iOS)

## 2026-11-18 — База: Telegram-iOS master `24638bc6` (13.2), Xcode 27.2 с `--overrideXcodeVersion`

Тегов релизов у Telegram-iOS нет (публикуется ветка master), поэтому фиксируем коммит `24638bc6` (2026-11-03,
`versions.json`: app 13.2, Xcode 27.1, Bazel 9.2.0). Он записан в `ios/scripts/common.sh` (`TGIOS_REF`).
Xcode у нас 27.2 — минорная разница. Make.py пропускает проверку по `--overrideXcodeVersion`, так делают и сами
разработчики Telegram. Если сборка упрётся в несовместимость, план Б: поставить Xcode 27.1 рядом и
указать его через `DEVELOPER_DIR` (sudo не нужен).

## 2026-11-18 — xray внутри процесса: своё ядро `XraygramCore` (Go c-archive), а не gomobile/`libXray/xray`

Варианты:
- (а) `gomobile bind` libXray → ObjC API `LibXrayInvoke`;
- (б) libXray `cgo_bridge` (c-archive, `CGoInvoke`) — как есть;
- (в) **свой маленький Go-пакет `ios/xraykit/go`** на libXray `share` + Xray-core `core` → c-archive → xcframework.

Выбрали (в):
- пакет `libXray/xray` под `GOOS=ios` навсегда включает режим Network Extension (GC 10 %, `FreeOSMemory` каждую
  секунду, лимит 30 МБ) — лишний расход батареи в главном приложении; и держит только один экземпляр;
- нам нужно несколько экземпляров (у каждой XRAY-записи свой порт: список прокси пингует все записи сразу);
- логика (ссылка → первый outbound → SOCKS5 с паролем) та же, что в `macos/core/main.go`, ~250 строк, тот же
  libXray `v1.261109.0` (`go.mod`/`go.sum` скопированы из macOS);
- c-archive + `apple_static_xcframework_import` в Bazel проще gomobile (никаких `gobind`, ObjC-обёрток и
  «iOS Simulator Runtime» для сборки); сборка ~30 с.

## 2026-11-18 — Новый тип `ProxyServerConnection.xray(link:)` (в отличие от macOS)

На macOS XRAY-запись маскировалась под SOCKS5 `127.0.0.1:<порт>`, а ссылка хранилась отдельно. На iOS так хуже:
порт живёт только в процессе (выбирается при старте), а настройки прокси хранятся в Postbox. Поэтому в iOS
ввели отдельный случай перечисления `.xray(link:)` (`_t = 4`). У него `host`/`port` — сервер из ссылки (для показа),
а в сеть он уходит через `mtProxySettings` → `XrayProxyManager.endpoint(for:)`.
Компилятор сам показал все `switch`, которые нужно поправить (~10 мест). Старые сборки Telegram прочитают такую
запись как SOCKS5 без адреса, но здесь это не важно.

Логин SOCKS5 = `xg` + FNV-хэш ссылки, пароль случайный на процесс. Поэтому у разных XRAY-записей
`MTSocksProxySettings` всегда различаются, и при переключении сеть переподключается.

## 2026-11-18 — `XraygramKit` — отдельный модуль на Foundation, зависимость TelegramCore

- Код, который можно переиспользовать: `ios/xraykit/` (Go + Swift). В дерево Telegram его кладёт `build.sh prepare`,
  в патч он не входит (один источник правды). Будущий Swift-клиент для macOS (TelegramSwift на том же TelegramCore)
  возьмёт тот же модуль и macos-срез xcframework.
- Ядро линкуется только через TelegramCore → `TelegramCoreFramework` (один Go-рантайм на процесс).
  SettingsUI и TelegramUI импортируют `XraygramKit` только ради Swift-API, а rules_apple не дублирует
  статику уже слинкованного фреймворка.
- Жизненный цикл: `retain`/`release` (активная сеть держит активную запись, проверка в списке держит свои записи),
  экземпляр без пользователей гасится через 15 с; порт ссылки запоминается на время жизни процесса.

## 2026-11-18 — UX как на macOS

- Экран «Proxy» (добавить): первым идёт тип **«XRAY (VLESS)»**, он выбран по умолчанию. Под ним одно многострочное поле
  «ССЫЛКА» (vless/vmess/trojan/ss/hysteria2). Если ссылка уже в буфере, она подставляется сама. Ниже строка
  «Сервер: vless · host:443 · имя» или «Ошибка: …». Готово → запись сохраняется, становится активной, прокси
  включается («сохранить и подключиться»).
- В списке запись выглядит как `XRAY · <имя>`, статус и пинг как у остальных, при ошибке запуска — «XRAY: <ошибка>».
- XRAY-записи не шарятся (кнопки «Поделиться» нет, в «Share proxy list» их нет): в ссылке секрет.
- Строки только по-русски, без локализации (как на macOS).
- **Отличие от macOS**: iOS 27 не даёт прочитать буфер без действия пользователя, поэтому вместо автоподстановки —
  строка «Вставить ссылку из буфера» над полем; поле принимает обычную вставку. Return убирает клавиатуру.
- **Кнопка «Прокси» на экране ввода телефона**: штатно экран прокси до входа доступен только после таймаута;
  у друга Telegram заблокирован с первого запуска, поэтому кнопка нужна всегда.

## 2026-11-18 — Ребрендинг минимальный

Имя на экране — **Xraygram** (`CFBundleDisplayName`). Bundle id задаётся конфигурацией, по умолчанию
`io.github.vizacv.xraygram`; поменять можно в `.secrets/ios.env`. Группа — `group.<bundle_id>`.
Данные не пересекаются с официальным Telegram (другой контейнер). Иконка пока Telegram: для личного теста этого
хватит, для раздачи нужна своя. URL-схемы `tg://` остаются: если на телефоне стоит и официальный Telegram, iOS
сама выберет, кому открыть ссылку.

## 2026-11-18 — Подпись: бесплатный Apple ID, сборка без расширений

Решение владельца — бесплатный Apple ID. Он позволяет App Groups, Keychain sharing и Background modes, но не Push,
iCloud, Siri и Associated Domains. Ещё ограничения: 10 App ID за 7 дней и профиль на 7 дней. Поэтому:
- собираем с `--disableExtensions` (только основное приложение = 1 App ID + 1 App Group);
- `aps-environment` пустой (патч Make.py), `enable_siri/icloud = false`;
- профиль выпускает сам Xcode через проект-заглушку (`ios/scripts/signing-stub.sh`) с тем же bundle id и App Group,
  а подписывает Bazel тем же профилем (`--codesigningInformationPath upstream/xraygram-ios/signing`);
- ставим на iPhone через `xcrun devicectl device install app`.
Последствия: нет push и входящих звонков в фоне, нет Share, виджетов, Siri. Подробно — `research.md`.

## 2026-11-18 — Экран «Подключение через XRAY» (решение владельца для всех платформ)

Правила — `macos/decisions.md` («Экран XRAY»), на iOS они повторены так:
- **Состояние** хранится в `ProxySettings` (TelegramCore, общие настройки прокси): `xraygramDirectAllowed`
  («напрямую» выбрано явно) и `xraygramSavedLinks` (все когда-либо добавленные XRAY-ссылки). В Postbox они
  пишутся новыми ключами `xgDirect`/`xgLinks` (`decodeIfPresent`, старые данные читаются).
  `xraygramNetworkBlocked` = нет XRAY-записей и не «напрямую»; отсутствие настроек (первый запуск) = блокировка.
- **Блокировка** — в `ProxySettings.effectiveActiveServer`: при блокировке он возвращает «чёрную дыру» SOCKS5
  `127.0.0.1:1`. Через это место идёт вся сеть MTProto (оба движка, все аккаунты, вход). Сохранённые настройки не
  меняются, блокировка накладывается сверху.
- **Поиск запасных адресов MtProtoKit** (`MTBackupAddressSignals`: DoH Google/Cloudflare, затем прямые MTProto к
  найденным IP с **явно снятым** прокси) при любом заданном прокси не запускаем (`MTContext.m`). Это закрывает и
  утечку мимо xray в обычном режиме XRAY, не только блокировку.
- **Общие правила изменений** — `xraygramNormalizeProxySettings` в `updateProxySettingsInteractively` (через неё
  идут все изменения): новая XRAY-ссылка запоминается и сбрасывает «напрямую»; если убрали активную XRAY-запись,
  а другие есть, активной становится другая (upstream выключал прокси — молчаливый уход напрямую).
- **Экран** — `XraygramGateController` (SettingsUI, ItemList): текст, «Сохранённые серверы» (если есть) +
  «Новая ссылка», поле со вставкой и превью, «Подключить», внизу «Подключиться без XRAY (напрямую)» → алерт с
  красной кнопкой. Показ — `AppDelegate.updateXraygramGate` по подписке на настройки прокси. Экран встраивается
  оверлеем в верхний `NavigationController` окна, поэтому его показывают только после появления экрана входа или
  чатов (экран входа сам показывается на `.root` и иначе перекрыл бы его). Смахнули или закрыла смена экрана —
  показываем снова через 0,5 с. Блокировка снята — закрываем.
- **Удаление последней XRAY-записи** в списке прокси → алерт «Это последняя XRAY-запись» (если не выбрано
  «напрямую»), после удаления экран появляется сам и предлагает сохранённую ссылку.
- Отличие от macOS: буфер на iOS 27 без действия пользователя не читается, поэтому «если в буфере ссылка — выбрана
  Новая ссылка» не реализовать; по умолчанию выбран первый сохранённый сервер, если он есть.

## 2026-11-18 — Звонки через xray: патч tgcalls + только «проксируемые» версии

- Патч `macos/patches/tgcalls/0001-socks5-tcp-relay.patch` перенесён в сабмодуль `submodules/TgVoipWebrtc/tgcalls`
  (iOS-версия tgcalls новее: `c1de0882`; не лёг один фрагмент-лог в `InstanceV2ReferenceImpl.cpp` — поправлен руками).
  Канон для iOS — `ios/patches/tgcalls/0001-socks5-tcp-relay.patch`, применяет `build.sh src`, выгружает `update-patch.sh`.
- **Найдено на iOS, нет на macOS:** iOS регистрирует ещё `InstanceV2CompatImpl` (14.0.0) и `InstanceV2PumpImpl`
  (18.0.0/19.0.0, wasm-ядро). Патч их не трогает, а Pump вообще не принимает прокси — звонок такой версии шёл бы
  напрямую. Поэтому при активной XRAY-записи `CallSessionManager` предлагает и принимает только 7–13
  (`InstanceV2Impl`, `InstanceV2ReferenceImpl`); если собеседник умеет только другие — звонок не соединится, но и
  напрямую не пойдёт (как на macOS: «лучше не соединится, чем тихая утечка»).
- Как на macOS: для XRAY прокси в звонке включён всегда (без галки «Use for calls», она скрыта для XRAY), P2P выключен.
- Групповые звонки/видеочаты — пока без предупреждения «Без xray» (на macOS оно есть) — следующий шаг.

## 2026-11-18 — Выравнивание по спекам продукта (PAR-01/02/03/04/05/07/09/14, BUG-13/14)

- **Тексты** — все строки XRAY-экранов и алертов в `XraygramKit` (`XrayStrings`, RU/EN по таблицам FEAT-01…04, 15).
  Язык: русский, если язык приложения русский, **или** язык приложения по умолчанию (en), а система на русском —
  до входа Telegram ещё не предлагал сменить язык, а друг с русским iPhone должен видеть русский. Иначе английский.
- **Ошибки ссылки** — ядро (`XGCheck`/`XGStart`) отдаёт `code`: `empty`, `web_link`, `unsupported`, `incomplete`,
  `start_failed`, `no_port`, `other`; текст выбирает UI (`XrayError.userMessage`). Для `unsupported` сырой текст
  libXray содержит саму ссылку — наружу его не отдаём. Тот же код пригодится macOS (`xraygram-core check`).
- **Вставка из буфера (BUG-14)** — системная кнопка `UIPasteControl` (iOS 16+) в своей строке списка
  (`XraygramPasteItem`): вставка без запроса разрешения. Подпись у неё **системная** («Вставить»/«Paste»), текст
  «Вставить ссылку из буфера» задать нельзя — отклонение от FEAT-01, сообщено продукту. iOS 15 — обычная кнопка.
- **Сохранённые серверы** — не больше 20, новые сверху, дубли схлопываются (`xraygramNormalizeProxySettings`).
- **«Без XRAY» перед групповыми звонками** — в `PresentationCallManagerImpl`: `joinGroupCall`, `joinConferenceCall`,
  `scheduleGroupCall` (через них идут видеочаты, конференции, создание видеочата/трансляции). Просмотр
  RTMP-трансляции (`initialCall.isStream == true`) — без диалога: поток идёт по MTProto, то есть через XRAY.
- **PAR-15: звонок 1:1 → конференция** — тот же диалог в `PresentationCallImpl`, один раз за звонок
  (`xraygramAskBeforeConference`), только когда звонок шёл через XRAY (`proxyServer.xrayLink`):
  «добавить участника»/ссылка конференции (`upgradeToConference`) — «Отмена» оставляет звонок 1:1 через XRAY;
  принятие приглашения в конференцию, перевод в конференцию собеседником (`.switchedToConference`) и
  `inline_conference` — шаг придерживается в `updateSessionState`, «Продолжить» повторяет его с сохранённым
  состоянием, «Отмена» = положить трубку/отклонить (иначе звонок висит в «обмене ключами»).
- **Выключение «Use Proxy» при XRAY-записях** — алерт «Подключиться напрямую?» (переключатель сам не переключается,
  пока не подтвердили). Переход на не-XRAY прокси — без алерта.
- **Поделиться сервером (FEAT-15, этап 1)** — пункт в окне XRAY-записи (там, где у обычных прокси «Поделиться»):
  предупреждение → нативное окно (QR без текста ссылки, «Копировать ссылку» с `localOnly`, «Отправить…»
  `UIActivityViewController`, «Закрыть»). В «Share Proxy List» XRAY не попадает.
- **Иконка (FEAT-07)** — `XraygramAppIcon.xcassets/AppIcon.appiconset` (один PNG 1024 из `branding/ios`, кладёт
  `build.sh prepare`) вместо `Telegram.icon` (Icon Composer). Альтернативные иконки Telegram остались.
- **BUG-13** — схемы Telegram (`telegram`, `tg`, `ton`, `tonsite`, `tc`) больше не регистрируем; своя — `xraygram`
  (она же `app_specific_url_scheme`); `CFBundleName = Xraygram`.
- **Для QA (симулятор)** — XRAY-запись без UI: `SIMCTL_CHILD_XRAYGRAM_ADD_LINK` или `SIMCTL_CHILD_XRAYGRAM_ADD_LINK_FILE`
  при `simctl launch` (код только под `targetEnvironment(simulator)`).
